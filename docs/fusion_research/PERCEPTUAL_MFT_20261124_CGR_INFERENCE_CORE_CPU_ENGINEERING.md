# CGR补测推理核心与CPU证据

已实现冻结CGR条件的图像推理核心、只读门控统计和保留原编号的轨迹写入。原六组条件、13个角色/12个不重复Test对象及Dev选择保持不变。完整4/5卡调度、真实GPU工程门槛、七序列Test和逐方法成本仍待接齐，没有启动新GPU任务或新训练。

`tools/correlation_recovery_inference.py`使用原来的共享RGB编码器和CGR参数、预处理、局部检索、完整检测头及raw/priority读出。正常、实际IR图像roll和缺失分支分别处理；缺失分支传入空辅助特征与不可用标志。保留新鲜RGB和历史规范RGB两个不同来源。原来每视频独立样本批量为4，末尾保留短批；这不等于B1在线延迟，后续不能用共享生产时间冒充逐模型FPS。

原CGR每个条件单独回放两段Dev，`BaseTrack`编号计数跨视频延续。新写入核心为每个条件持有独立计数，按同一视频次序延续编号；每段开始重新创建跟踪器，Kalman状态、目标轨迹及关联证据全部重置。编号在输出当时确定，没有事后重新编号，也没有把上一视频的对象信息带入新视频。

目前已经完成的证据为：

- `PERCEPTUAL_MFT_20261124_CGR_NEW_STREAM_FULL_DEV_PROOF.json`：复用原真实检测，八个冻结正常/配对条件各4834帧，交错执行新写入核心。两段视频共16份完整轨迹文件逐字节等于原结果，包括身份编号、框和分数。没有新增图像编码、GT读取或准确率评估。
- `PERCEPTUAL_MFT_20261124_CGR_REAL_PIXELS_CPU_PROOF.json`：真实Train的BT-003第1–2帧及固定11月IR，12个冻结条件的输出逐项等于原CGR计算；六个零分支的完整检测头/NMS和训练后缺失回退精确，源RGB权重及BN保持不变。使用原半精度预处理数值和FP32 CPU网络；不证明GPU FP16结果。执行118.252秒是这次工程检查总耗时，不是方法FPS。
- `PERCEPTUAL_MFT_20261124_CGR_INFERENCE_CORE_CPU_TESTS.json`：新核心与共享轨迹工具一起检查，覆盖批内其他样本不能改变当前样本、缺失图像、历史RGB优先整合、半精度特征修正统计及两视频交错编号。测试前后所记录源码保持一致。

`CorrelationGateObserver`记录每层实际学习sigmoid门控、教师置信掩码后的trust、输入可用/缺失数和经过输出dtype转换后的特征修正RMS。统计覆盖可用帧的特征网格，包含填充区域，不使用GT鱼体掩码；缺失帧不虚构gate样本。高置信特征位置不变不能推出其邻域检测框不变。临时gate张量在每层前向完成后清空；正式逐方法成本应关闭观察器，共享诊断生产则注明其开销。

这些记录没有新增HOTA或贡献。该路线仍是既有局部相关架构的训练变化，原IR课程Dev47.628、去课程49.186的负证据保留。后续须先接齐调度，在现有全量Train、结构补测和原生金字塔结束后，使用物理4/5卡验证源/零/缺失、所选原Dev的实际图像预测和全部正式Test；不使用旧提取器写死的2/3卡，不伪装CUDA映射，不抢占健康作业。
