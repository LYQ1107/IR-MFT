新增独立计时内核、完整原始来源核验和 `benchmark_fusion_memory.py` 入口。

## 实现范围

每个冻结配置分别运行每段 32 帧：先用独立状态验证前缀，再用新状态运行
8 帧预热和 24 帧计时。状态从预热连续进入计时，不能在第 9 帧重置；七段
共 168 个计时帧。这是前缀抽样成本，不是完整 15985 帧 FPS。GPU 同步位于
计时边界，范围包括图像 IO/解码/字节 hash、RGB/辅助编码/光流、head/NMS、
ROIAlign、ByteTrack/记忆；权重加载、离线 IR 生成和验证序列化另行排除。
全部控制都读取并 hash 未使用 IR 字节作相同来源核验，RGB 不解码或使用 IR。

全量 F4 生产及原始父模型的完整 packet/MOT 必须绑定。原生家族没有保存
逐帧检测前缀，因此使用原完整图像/检测摘要与原轨迹文件前缀，加当前 F4
实际前缀核对；空间家族另须核对其原保存的前缀。不能要求原生家族不存在
的字段，也不补造原记录。缺失 IR 必须匹配同权重/同阈值新鲜 RGB 记忆。

参数逐个报告，非参数轨迹/递归状态按帧抽样记录逻辑数组字节。该值排除 NN
及 Python 堆，不能标为全序列真实峰值。GPU 峰值逐配置重置；主机 RSS 是
进程累计峰值，明确不冒充逐配置隔离峰值。不会把多配置共享前向 FPS 当作
单方法速度。已完成配置有独立持久记录，可在同一登记/来源下接续。

## 检查与实际结果

23 项人工图像/模型/时钟/完整长度元数据检查通过，覆盖新状态、预热连续性、
错源、输出摘要、失败清理、质量/时序/空间三类模块、原生无前缀、错位与缺失、
错误阈值及全量原 MOT 变动。它们不是训练、真实 Test 或 GPU 成本证据。
首轮人工样例漏登记摘要，12 通过/8 失败；补齐样例，未放宽生产核验。

固定 Train BT003 的前 8 帧，用原 RGB CPUFP32/480×864 做零记忆和 0.05
各两遍独立运行，共 32 次 RGB 解码，IR 字节只核验不解码；初次实际执行
131.155 秒、峰值 RSS1.547GiB，检测包及 MOT 前缀均精确匹配既有参照。
每配置只有 6 个 CPU 计时帧，不能作为正式 800×1440/GPU 成本或新准确率。
非零路径每遍实际 7 次关联成本调用、21 条正惩罚边，短片段 MOT 仍未变。

字节；不代表完整视频或 Python 进程峰值。初始配置原字节保留为 initial。
