# 输入一致性保护与训练队列恢复

IR完整Train在第6个宏循环读取缓存图像时触发原文件元信息保护，退出码1。总控及等待中的Dev、后续Test、结构补测和原生金字塔控制器按既定规则停止。RGB与灰度实际上均已完成72宏循环、20736更新、三遍全部27251帧；灰度完成证明已保存，未被误当作失败重训。

原读取器用设备号、inode、大小和mtime判定缓存是否变化，未记录具体失败路径或原RAM字节。IR目录是SSHFS挂载；对失败窗口128幅当前文件的三轮复核没有重现该异常。因此只能确认元信息保护触发，不能宣称已经证明原图内容改变，或已经确定SSHFS inode是具体根因。原状态、日志和IR第5宏循环检查点均保留在独立工作盘的`structural_input_metadata_guard_failure_20261124`。

新增`ContentVerifiedTrainImageReader`在元信息变化时重新读取，必须与缓存字节完全相同才能继续。缓存淘汰后也保留首次内容SHA256；真正的字节变化仍立即拒绝，并报告路径和摘要。输入不变时的解码、归一化和NN计算不变，没有修改或重新生成任何原始RGB/IR图像，也没有新增图像/FPN磁盘副本。原读取器源文件保留，已完成RGB/灰度的来源哈希仍有效。

四项CPU检查覆盖同字节元信息更换、真实内容变化、淘汰后检查及原RAM限制。六段Train的24幅实际RGB/IR文件，旧读取器、新读取器和直接OpenCV读取逐像素一致。证明见`PERCEPTUAL_MFT_20261124_CONTENT_VERIFIED_READER_CPU_PROOF.json`；当前文件诊断见`PERCEPTUAL_MFT_20261124_SSHFS_READER_DIAGNOSTIC.json`，其中明确标记没有复现原故障。
