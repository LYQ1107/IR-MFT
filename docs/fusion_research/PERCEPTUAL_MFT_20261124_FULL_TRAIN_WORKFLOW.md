# 全量 Train：六组受控实验与完整评估流程

本轮保留 11 月新版 DiffV2IR 原始文件、固定六段 Train / 两段 Dev / 七段 Test、RGB 初始化和 ByteTrack 主协议。只使用物理 GPU4、5，模型种子固定为 0。目标仍为完整 Test HOTA 至少 34.529，验证 2–3 项独立贡献；当前尚未达到。

此前 1,152 帧缓存占 Train 的 4.227%，重复遍历不能增加独立观察。本轮每个完整遍历都覆盖 **27,251 个 Train 帧**。为了同视频帧对和优化器批次对齐，每遍历有 397 次补齐访问，合计 27,648 次样本访问。三遍历合计 82,944 次访问、20,736 次 batch4 更新。

原训练函数中的 `epoch` 在这个入口里是优化器的宏循环：每宏循环 288 次更新，24 个宏循环完成一次全量遍历；72 个宏循环等于 **3 个全量 Train epoch**，不是 72 个。保存第 24/48/72 个宏循环检查点，即完整遍历 1/2/3 的模型。

六组共享完全相同的实际帧顺序、参数量 145,600、初始化、原损失、训练输入 480×864 和推理输入 800×1440。硬双向检查保持关闭，残差 RMS/tanh 和最终 logit 边界始终保留。冻结共享 RGB 编码器和检测头，不增加独立 IR 专家。RGB/灰度对照不能用旧缓存模型替代。

帧按视频自然长度参与覆盖，两个反例帧始终来自同一视频且互不相同；一个 batch 的两对帧允许来自同一视频。因此本轮同时改变数据覆盖、视频采样比例和总更新数，是新的同预算实验，不能把差异全部归因为单独增加独立帧，也不把增加训练数据称为创新。

全部六次拟合前分别做 20 个真实 GPU 更新检查。此前已完成 CPU 两步更新一致性，实时 B1 GPU 特征/目标/描述和两步更新核验也在 2026-11-24 通过。初次非确定性 CUDA 核验出现最大 3.73e-9 权重差；启用确定性算法后严格比较通过，原失败记录保留。确定性设置用于这个工程对照，不表示此前非确定性训练被逐位重现，或未来训练的全部步数已被核验。

已预注册 50 项完整 Dev：六次拟合 × 三个完整遍历检查点 × raw/priority 两策略，共 36 项；另 12 项真实 IR 错位/关闭干预和两个 RGB 来源对照。正常主 IR、同预算 RGB/灰度各有相同六次选择机会。只按完整 Dev HOTA 选择，平局依次选较早检查点、raw。去除版本同时报告主模型相同遍历/策略和各自 Dev 最佳结果，不叠加这些条件差值。

在首次读取新模型准确率前，核对 8 帧零修正的 17 条流、32 帧训练模型的 49 条流，以及完整两段 Dev 的来源/前缀/密集 RGB 坐标。关闭模态的 raw 必须严格回退新鲜 RGB，priority 必须严格回退原始 RGB。新的回放入口已在全部 4,834 帧上核对：39 指标、276 列官方 CSV 和两段轨迹文件全部等于原始 RGB，HOTA 47.579。

50 项 Dev 完成后，冻结 13 个 Test 比较角色，相同配置去重推理；每个正式模型均测满七序列 15,985 帧，包括负结果。固定主模型不按 Test 换成更高分消融。先独立测量所有正常正式配置的单方法耗时，再进入 Test，避免自有 GPU 任务互相争用。单方法测量同时保留文件输入和内存输入，核对真实 raw/priority 输出，排除伪红外生成，报告 B4 吞吐及自身显存，不声称 B1 延迟或实时。

队列依赖是：原 S/C/R 组合 Test 的七个神经生产器退出 → 实时 GPU 两步一致性通过 → 六组拟合 → 50 项完整 Dev → 冻结选择及单方法耗时 → 全部正式 Test → 完整指标导出。2026-11-24 已恢复前三个等待控制器，首批 RGB/灰度通过真实 20 次更新检查并进入正式训练；后续状态以工作盘对应 state JSON 和实际进程为准，登记时的 `*_started=false` 是快照。

核心文件是 `configs/perceptual_structural_fulltrain_study_20261123.json`。派生构型保留父版本的历史 `reason/hypotheses/initial_fits/created_utc` 字段，实际拟合清单、登记时间和预算以 study 文件及 `StructuralFactorial` 标志为准；这些历史字段不会启用旧硬循环候选。

入口为 `tools/start_structural_full_train_pipeline.py`，会核对已经登记的代码、配置和完整评估工具，再启动拟合、Dev、后续评估三个控制器。已经运行时不要重复启动或因观察超时重建状态；失败应保留日志和权重，核对真实进程后修复恢复。

不新增图像/FPN 磁盘副本；地址文件只有 235,236 字节，留在工作盘。单进程只限量复用原始压缩图像字节，RAM 上限 8 GiB，插入前检查 40 GiB 可用内存储备；其他项目随后消耗的内存不可由该检查约束。工作资产上限 64 GiB、工作盘空闲储备 40 GiB。GitHub 仅推代码、配置、小型指标及分析，权重和数组不上传。
